# Офлайн-режим и синхронизация

На планшете работает лёгкое POS-приложение с локальным HAL. Отдельного сервера и серверной СУБД в магазине нет. Приложение хранит встроенный зашифрованный кэш утверждённых товаров, цен и применимых промо, а также устойчивый журнал операций. При обрыве связи кассир принимает наличные, HAL передаёт команду фискальному регистратору, который печатает чек и сохраняет фискальные данные для последующей отправки в ОФД. Онлайн-списание баллов недоступно, начисление ставится в очередь. Карты доступны только при работающем канале банка и подтверждении терминала. В базовом офлайн-сценарии гарантируются наличные.

Каждая продажа получает уникальный ID и последовательный номер устройства. До фискализации сохраняется намерение, после неё сохраняются результат и номер фискального документа. Если приложение перезапустилось между этими шагами, оно сверяет результат с регистратором, не печатая чек повторно. При восстановлении связи журнал отправляется в Cloud Backend по порядку с повторами до подтверждения. Backend устраняет дубли по ID, сохраняет продажу и передаёт события в SAP, лояльность и Smart Fulfillment через очередь. Запись удаляется из очереди планшета только после устойчивого подтверждения сервера. Ошибки интеграции остаются в очереди на повтор или разбор оператором.

Каталог загружается по номеру версии и переключается целиком после проверки целостности. Проданные товары сохраняют цены из чека, новые цены не меняют прошлые продажи. Остатки уточняются по событиям продаж, конфликт доступности заказа разбирает Smart Fulfillment. Баллы начисляются однократно по ID продажи. Контроль синхронизации показывает возраст очереди, ошибки и свободное место. При повреждении кэша или заполнении журнала продажи блокируются до восстановления. На пилоте проверяются обрыв связи, перезапуск планшета и повторная доставка одной продажи.
